## 产品范围

用户提出目标，GUI 模型看当前画面，连续给出一步语音指导，由用户自行操作。
面向 Android 的一般App及系统任务。没有自动点击，不提供付款、转账或密码验证码输入指导。
不以完整地图为上线前提；旧地图、静态安装包资料和训练数据保留，但本版导航没有接入旧地图检索。

APK 移除无障碍服务、训练/学习入口、训练密码及相关插件。旧手机私有目录和服务器
训练数据不删除。旧版若还有未上传材料，先用旧版补传；新版不继续处理旧版训练队列。

## 用户操作

1. 打开小路，输入目标，或“说出目标”后检查、修改识别文字。
2. 首次确认云端画面分析说明；另行选择是否“同意分享”结构化反馈。
3. 开启“悬浮小路”并允许系统悬浮显示。授权返回后需再点一次开启。
4. 开始导航并允许屏幕共享，App 自动退到后台，用户自行打开抖音、操作。
5. 点击悬浮入口可以重听、暂停/继续、反馈“没有找到”“这一步不对”，或确认完成/结束。
6. “我已完成”需要再次确认；普通结束不会算成功。“申请提交”不等于“退款到账”。

回到小路前台或系统停止屏幕共享会暂停采集，避免识别自己的指导页面。
恢复时重新申请共享并重新观察当前画面。进程被杀后不自动恢复屏幕共享，须重新开始任务。
首次分享选择可在设置更改，从下次任务生效。

## 实现与状态机

`MainActivity` 处理系统共享、悬浮窗、系统语音输入和中文 TTS；
`ScreenCaptureService` 提供 MediaProjection 帧；`ConsumerSession` 管理任务、请求及反馈。

```text
目标 -> session -> 系统授权 -> 后台视觉导航
                         -> 暂停 -> 再授权 -> 重新观察
视觉结果 -> 一步指导 -> 等待用户 -> 新画面 -> 视觉结果
视觉疑似完成 -> 等待用户确认 -> 完成或继续
用户结束 -> 停止采集 -> 上传结果 -> 待审核候选
```

原生截图检查间隔 300ms，缩小一半、JPEG 65；客户端只检测变化，不再叠加时间节流。
节流期间合并为最新待采画面，不直接丢弃末帧；开始监听时补发内存中的最近帧，停止时清除。
这不是“每 300ms 完成识别”：同一次任务最多一个视觉请求在途，保留最新待处理帧。
模型和网络耗时额外计算。暂停/新任务使旧结果失效；同一页面目标去重，避免换句话重复打断。
当前不做本地视觉推理，也没有达到亚秒端到端播报保证。

语音默认简洁，可切换详细；优先选择手机现有中文女声，无法保证所有手机声音相同。
语音输入依赖系统识别服务，未配置统一云端 ASR。在没有识别服务的 vivo 上可用文字，
但仍需实际验证语音入口。不能把构建成功当作真机声音验收。

## API

Base URL：`https://loop-lulu.com/intermap/api/consumer/`。

| POST 路由 | 请求 | 权限与结果 |
| --- | --- | --- |
| `session` | `goal`, `consent`, `environment` | 返回随机 bearer token、session_id、30分钟有效期 |
| `frame` | `image`，JPEG data URL | bearer；返回 page_type/action/step_text/expected_result/target_role/target_key/step_id |
| `feedback` | `feedback`, `event_id`, `step_id` | bearer；纠错、完成、取消及客户端异常 |
| `review` | `password`，可选 `session_id` | 现有训练密码；查看最近100次汇总，或指定任务详情及待审核分组 |

生产 Nginx 将 `/intermap/api/consumer/` 转发到 3011 端口的 `/api/consumer/`。
仅信任来自本机代理的 `X-Real-IP`，bearer header 保留，读取超时25秒、请求体上限3MB。
`review` 未接入旧网页复盘 UI，维护者通过受保护接口或服务器文件查看，不对普通用户开放。

后端 `consumer_navigation.js` 使用 capture service 的 `ARK_API_KEY`；默认模型
`doubao-seed-2-1-turbo-260628`，可以用 `ARK_MODEL` 覆盖。密钥不进入 APK。
只有明确纠错、且配置 `DEEPSEEK_API_KEY` 时才切换 `deepseek-flash`。
生产尚未配置 DeepSeek，未验收该分支。主路不是两次串行 GUI + LLM 调用。
`TRAIN_PASSWORD` 为后台必需配置，缺失时验证失败，不再使用源码默认密码。
生产沿用用户原密码，私有文件 `/etc/intermap-consumer-auth.env` 权限600，由systemd
`intermap-capture.service.d/consumer-auth.conf` 注入；这些私有配置不能上传GitHub。

试用保护限制：每IP每小时20次新任务、全站200次新任务；每任务最多120次视觉请求，
全站每小时1500次视觉请求；反馈每IP每小时600次。超额时暂停并提示，不是商用配额方案。
会话服务重启会中断当前导航，需要重新开始；反馈重试不受此影响。

## 数据收集与上传

导航需要将授权画面临时发送云端模型。**未选择分享时，后端不写本版反馈文件。**
选择分享后自动写入 `/var/www/intermap-data/consumer_feedback_v1/<session_id>.jsonl`。
文件权限600、目录700，不在公开静态网站目录。

- `started`：任务类别、App版本、机型、系统/显示环境、可获取的抖音版本。
- `observation`：App枚举、页面类型、建议动作、目标语义类别、step_id、模型和识别耗时；
  还记录固定公共控件白名单（如“我的订单”“申请退款”）、方位枚举和图标类别。
- `feedback`：没有找到、步骤不对、完成、取消、客户端异常；关联当时步骤。
- `diagnostic`：服务端模型错误的固定错误码，不保存原始响应或屏幕文字。
- `candidate_path`：本次观察序列、用户自报结果、`actual_clicks_known:false`、`ready_for_navigation:false`。

原始目标文字、指导话术、任意控件原文、截图及录像不写入反馈日志；公共控件标签只允许固定白名单。
目标和近期指导只在当前
服务会话内用于推理。结束后清除其内存内容。模型服务商自己的处理/保留政策仍需正式隐私评估，
不能因为本机不落截图就宣称“完全不处理个人信息”。

完成、取消、纠错和客户端异常先写手机私有队列，再后台上传，单次反馈等待上限4秒；
每30秒、下次打开或开始任务时重试。24小时内凭收据恢复服务重启后的反馈上传；重复 event_id
不会重复记账。超过24小时的待发送反馈过期清除，因此不是无限期离线保证。
队列只含 token、反馈枚举、步骤编号和时间，不含目标或画面；有待传项时首页显示条数。
识别结果由服务器直接落库，不依赖退出时统一上传。

## 怎么利用这些数据

`review` 自动按任务类别、设备环境及连续页面序列分组，统计用户自报成功次数。
不同版本分开；相邻重复页面折叠；结果仍为 `pending_review`。
本版没有无障碍，所以**不知道真实点击坐标**，不能证明用户按建议点击，返回也不能自动判错。
页面类别只是粗粒度节点，不足以直接生成精确的按钮级完整地图。

后续人工核实高频任务、失败步骤和结果条件，再补最小必要的标注或同意后的专用采集，
将真实证据转为带环境条件的路线。先用回归测试验证，再单独发布；不要直接微调模型或
把用户自报成功的轨迹当成 Golden Flow。本版没有自动训练模型权重，也没有自动发布/检索候选图。
旧实时训练、视频抽帧、网页推测、APK静态证据保持各自目录和可信等级，不混成已验证数据。
