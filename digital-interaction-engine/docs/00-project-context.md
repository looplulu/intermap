# 小路产品共识 V1.1

更新日期：2026-10-31。当前为商业化联网试用阶段，优先于早期比赛、公益和人工训练规划。
本版实现及验收边界见 [1.1试用说明](14-consumer-pilot-1.1.md)。

## 一、项目简介

小路是面向中国中老年智能手机用户的商业产品。目标用户能够进行基础点击，
但在具体手机任务中遇到入口难找、步骤不明、结果不确定和走错不会恢复的问题。

产品提供连续语音导航：用户表达目标，系统解释当前应该做的一步，用户自己
操作，系统根据实际页面继续引导。1.1由视觉模型推理和 Navigation Session 支撑，
先获得市场反馈，不以预先建好完整流程图为使用前提。

产品范围和成效以真实使用与商业验证为准，不再围绕比赛展示制定。AI 眼镜、
平台化和长期任务记忆均不是当前开发重点。

## 二、V1.0 核心变化

**从"先建地图，再导航"变为"边导航，边建地图"。**

V1.0 的用户目标：

> 用户只表达一次目标，依靠连续指导独立完成受支持的手机任务。

地图成长是提高正确率、减少返工和降低维护成本的技术手段。真实交互形成
候选证据，经审核、发布和回归验证后才能改善下一次导航。

## 三、产品定位

产品定位：**Continuous Task Navigation（连续任务导航）**。

用户通过文字或语音表达一次目标（如“我要退款”）。系统持续识别页面、
定位任务状态、主动播报下一步，用户无需反复询问“下一步”。用户保留所有
点击、输入、选择和确认的操作权。

输入与输出要求：

- 文字目标输入是一级入口，与语音输入同等重要，不能依赖语音才能启动任务。
- 部分目标用户使用方言，语音识别出错时可以编辑识别文字或直接改用文字输入。
- 识别结果有歧义时简短确认目标，不能默认把不认识的需求变成退款。
- 导航默认简洁：先说位置，再说当前可见文字或目标名称，有图标才补充外观。
- 每次只讲当前需要执行的一步，同时保留当前步骤文字。
- 用户可以暂停、重听、切换详细引导或结束任务，不因操作慢而判定成功。
- 需要滑动、返回或等待时明确说出对应动作，不强行把每一步都生成为点击。

## 四、V1.0 四个核心能力

### 能力一：Task Recognition

用户通过文字或语音表达目标。系统识别 Task，并结合当前 App 和页面执行；
必要时确认 App 或目标对象，不把用户未表达的信息当成已知事实。

### 能力二：Continuous Navigation

进入任务后，系统持续运行：

```
用户操作 -> 页面变化 -> AI识别 -> 定位当前节点 -> 自动播报下一步 -> 等待页面变化
```

### 能力三：GUI + 推理，逐步积累可验证证据

- GUI + 模型推理识别当前实际页面、任务状态和可见目标，连续给出一步指导。
- 已有交互资料保留为研究依据；1.1主链路尚未接入检索，不能声称已用旧地图保证准确率。
- 未来加入经审核地图时必须匹配系统、手机、App版本和业务状态，不能强行套用旧路径。

运行顺序：

```text
文字或语音目标
-> GUI 识别当前 App、页面与状态
-> 结合目标和近期导航上下文推理，定位当前可见目标
-> 播报一步，等待用户操作
-> 用实际结果核对预期转移，继续导航或重新定位
```

不同系统和版本可能改变整个流程。若适用条件不满足，不能强行套用旧路径。
有可靠地图证据时，不能仅凭“订单通常在个人中心”等通用经验改变已验证路径。

Ground Truth 不保证对所有账号、订单状态和版本成立。目标看不清或证据冲突时
需要重新识别或请求用户澄清，不能为了保持连续播报而猜测关键步骤。

### 能力四：Interaction Learning

在明确告知与授权的采集模式下，保存最小必要且脱敏的交互证据。证据形成
Interaction Flow 候选，经审核后更新地图。采集成功、候选生成和导航效果
改善是三个需要分别验收的环节，不把上传成功等同于训练完成。

## 五、为什么选择中老年人

优先服务的用户能够完成基础点击，但在具体任务中常遇到三个问题：

1. **不知道眼前是什么** — 这个按钮是什么意思？这个页面在干什么？
2. **不知道点击以后会发生什么** — 会不会扣钱？是不是自动续费？
3. **不知道出错怎么办** — 能不能返回？钱还能不能退？

产品要帮助这些用户建立**数字世界中的控制感**。这是目标人群假设，不能
泛化成所有中老年人都不信任自动操作；后续以用户试用验证细分人群。

我们的产品理念不是 **Replace Human（替代）**，而是 **Guide Human（引导）**。

## 六、核心设计哲学

**不要为了 AI 去设计地图，而是为了地图去使用 AI。**

**不要先写数据库，先写 Navigation Session。**

真正的产品核心不是数据库，而是连续导航状态机。整个系统围绕一个 Session 运行。只要 Session 能跑起来，哪怕地图里只有 5 个节点，整个产品的交互就已经成立了。数据库只是这个状态机的知识来源。

## 七、Growing HD Map

地图不是一次性建立，而是 Growing HD Map。

- 初始：GUI + 推理运行，既有 Golden Flow 和静态资料保留但不强制套用
- 随着授权采集、审核和版本发布：不断补充、修正
- 以受支持任务的完成率和维护成本衡量价值，不承诺完整覆盖所有 App

真实操作、人工标注和审核共同提供证据。自由探索可以发现节点和连接，任务
目标、完成条件和风险仍需确认。

1.1不再要求用户专门进行无障碍训练，优先从用户同意后的真实导航反馈积累证据。
下列是后续高可信路线应具备的证据，而非当前纯视觉版本已能全部采集：

- App 身份及版本、系统版本、设备与显示环境；
- 操作前的页面和业务状态；
- 实际动作、目标文字或图标、可获得的位置证据；
- 操作后的页面、状态及结果；
- 人工修正、证据来源和审核状态。

用户实际点击与模型建议点击必须分别记录。坐标属于具体画面的定位证据；
跨系统、手机和版本复用依赖组件语义与状态条件。相同名称的页面、入口或按钮
不能直接合并，不同环境下的已验证变体可以共同归属一个任务。

## 八、V1.0 不做

- 自动点击 / 自动操作手机
- 完整互联网地图
- 所有 App / 所有 Task
- 长期用户记忆 / 商品记忆
- AI Agent

## 九、数据采集原则

产品要求：不长期保存完整录像、聊天正文、订单内容或其他无关个人信息。
屏幕识别需要临时处理用户授权的画面；地图学习仅保留最小必要的脱敏交互证据。

这是一项待验收要求，不能因未保存截图就宣称已完全脱敏。当前训练中的页面
文字、本地文件和服务端事件都需要检查，所有训练写入入口必须在服务端鉴权。

```
Task: Refund
App: Taobao
Node: Order Detail
Action: Refund Entry
Result: Success
Duration: 5s
Confidence: 0.94
```

所有数据围绕 Interaction，而不是用户。

## 十、V1.0 成功标准

1. **独立完成任务**：用户输入一次目标后，无需开发者协助即可完成受支持任务。
2. **及时且正确地引导**：记录页面变化至实际出声的延迟，以及错误、重复和过期指令。
3. **可恢复且结果准确**：走错能恢复，成功、取消、暂停和失败明确分开。
4. **地图改进可复现**：一次纠正经审核发布后，在固定回归样本和新变体中验证效果。
5. **商业可持续**：验证付费人群、复用、获客成本和每个成功任务的服务成本。

地图覆盖率必须有预先定义的任务与状态分母，取消没有测量依据的 10%/30%/80% 目标。

## 十一、V1.0 支持范围

- 平台：Android
- App：优先打磨抖音，其他 App 的静态资料仅为候选研究基础
- Task：先验证退款主路径，再验证查订单、联系客服等相邻任务
- 路径规划与感知：GUI + 推理，未来再加入条件匹配的已审核路线
- 采集：普通导航中的独立授权反馈；APK移除无障碍与人工学习/训练入口
- 输入：文字与语音目标输入；输出：连续语音和当前步骤文字

## 十二、项目原则

1. **先让连续视觉导航可试用，地图从可验证反馈逐步成长。**
2. **Flow 优先于 Page。**
3. **Task 优先于 App。**
4. **语义确定目标，播报采用实际可见文字。**
5. **地图记录稳定层，AI 处理动态层。**
6. **导航优先于执行。**
7. **建立用户控制感，而不是替代用户。**
8. **Session 优先于数据库。**
9. **导航即学习，学习即建图。**

## 十三、待验证的技术资产

- **Digital Interaction Ontology**（数字交互本体）
- **Digital HD Interaction Map**（数字交互地图）
- **Navigation Session**（连续导航状态机）
- **Interaction Learning**（交互学习机制）
- **Growing Map Pipeline**（地图自动成长体系）

资产价值需要用正确率提升、版本适配成本和真实使用验证，模块存在不等于
已经形成商业壁垒。

## 十四、商业化假设

盈利是项目目标。当前没有验证价格、收费对象或盈利模型，不预设老人端必须免费。

优先验证的方案：

- 个人或家庭付费：使用者本人或子女为持续手机指导付费，观察真实支付与续用。
- 机构采购：养老服务机构、运营商或其他服务渠道为其客户采购导航服务，验证
  安装协助、使用频率、支持成本和采购意愿。

一次性试用可用于验证价值。订阅、按需服务和机构授权都只是候选收费方式，
在使用频率和付款意愿明确前不锁定套餐价格。核心体验优先避免插入广告、
导购或与用户任务无关的销售建议。

成本需要同时计入视觉/API 调用、服务器、地图审核维护、安装支持、获客及渠道
费用。不能仅凭模型单次调用便宜推断项目可以盈利。

## 十五、当前实现与要求的区别

截至2026-10-31，1.1试用版实现文字/系统语音目标入口、悬浮任务入口、纯视觉连续指导、
暂停恢复、纠错与用户完成确认，以及独立授权后的结构化上传、补传和候选分组。
未完成 vivo 真机验收；统一云端ASR/TTS、亚秒延迟、精确点击采集、地图发布检索及
模型微调均不能视为已完成。本文定义产品方向，不作为实际效果已通过的证明。

## 十六、一句话定位

小路帮助中国中老年用户使用手机：用户用文字或语音表达目标，小路根据当前
画面一步一步主动讲解，由用户自己操作，持续引导到任务结束。
